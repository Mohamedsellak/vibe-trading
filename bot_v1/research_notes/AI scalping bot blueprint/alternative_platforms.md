# Alternative (non-MetaTrader) Trading Platforms and APIs for a Retail AI Scalping Bot (as of Nov 2026)

Scope: platforms/APIs a solo retail developer could realistically use for an automated, AI-driven scalper holding seconds-to-minutes. Each pricing figure carries the date of the source it was taken from; fees change often. Research was conducted 16–17 Nov 2026. Where official pages were blocked (IBKR commissions page returned HTTP 403, Bybit fee page timed out, OKX/Kraken fee pages returned only shells), the best available secondary source is cited and flagged.

## KQ1. What does each platform offer: API protocols, SDK maturity, streaming data, order types, paper trading, regulatory/geographic availability?

### Takeaway
Retail-accessible API surfaces fall into three families: (a) broker socket/REST APIs that require a running gateway (IBKR TWS/Gateway, cTrader Open API over protobuf), (b) pure cloud REST+WebSocket APIs with no local software (Alpaca, OANDA, Tradier, Saxo, TradeStation, all crypto exchanges), and (c) futures-specific execution networks (Rithmic R|API, Tradovate, CQG, NinjaTrader/NinjaScript). Crypto exchanges are the only venues offering FIX/SBE-style low-latency protocols to anyone with an account; in TradFi, FIX is either institutional-only (IBKR FIX via dedicated connection, LMAX) or offered free by cTrader brokers but with no documented latency edge.

### Cited Findings

**cTrader Open API / cTrader Automate / cTrader FIX**
- Open API messages are exchanged as JSON or Google Protocol Buffers; access requires a cTrader ID (cTID); by default all trading accounts at cTrader-affiliated brokers are supported; both demo and live accounts can be traded; official Spotware SDKs exist for C# and Python — [help.ctrader.com Open API Getting Started](https://help.ctrader.com/open-api)
- Rate limits (per connection): "maximum of 50 requests per second per connection for any non-historical data requests"; 5 requests/second for historical data — [help.ctrader.com Open API](https://help.ctrader.com/open-api)
- A forum reply says the limit is 50 req/s "per application" (vs. per connection in docs) and that exceeding it returns `REQUEST_FREQUENCY_EXCEEDED`; "If your application requires higher limits ... contact support@ctrader.com" — [cTrader community forum](https://community.ctrader.com/forum/connect-api-support/21640/); 2021 reply: no limit on subscribed symbols, limits apply to requests/sec and active connections — [cTrader community forum](https://community.ctrader.com/forum/connect-api-support/21640/)
- Official Python SDK: PyPI `ctrader_open_api` (also installable as `ctrader-open-api`), current release 0.9.2, built on Twisted; methods return Twisted deferreds; bundles protobuf message files — [PyPI ctrader-open-api](https://pypi.org/project/ctrader-open-api); [GitHub spotware/OpenApiPy](https://github.com/spotware/OpenApiPy); [help.ctrader.com Python SDK index](https://help.ctrader.com/open-api/python-SDK/python-sdk-index). A third-party guide calls the Twisted dependency dated — [m-ahmadi ctoa guide](https://m-ahmadi.github.io/ctoa/contacting-api/official-packages)
- cTrader FIX API: Spotware says it is "free for traders" and that traders can build "time-critical trading applications" on it — [Spotware cTrader FIX API](https://www.spotware.com/ctrader-fix-api). A forum user reports running FIX connections to 16 broker accounts including Pepperstone — [cTrader forum FIX](https://community.ctrader.com/forum/fix-api/40119/); another poster asked whether FIX has an internal latency advantage over regular cTrader execution and reported brokers say it does not (secondhand, unconfirmed) — [cTrader forum FIX](https://community.ctrader.com/forum/fix-api/11476/)

**Interactive Brokers (TWS API / Web API / FIX)**
- TWS API pacing: default 100 market data lines → "pacing limitation of (100/2)= 50 requests per second"; exceeding triggers error 100 and "The TWS will likely disconnect the client application"; whether a violation rejects or paces is a Global Configuration setting; "If the pacing limits are broken 3 times, the API session will terminate"; ">50 requests per second, some orders may be queued and delayed ... consider switching to FIX API"; FIX via IB Gateway: 250 messages/second — [IBKR TWS API pacing limitations](https://www.interactivebrokers.com/docs/tws-api/doc/pacing-limitations); [IBKR error codes](https://www.interactivebrokers.com/docs/tws-api/ref/error-codes)
- Web API (Client Portal): "global request rate limit of 50 requests per second for each authenticated username"; CP Gateway users "restricted to 10 requests per second"; per-endpoint limits e.g. `/iserver/marketdata/snapshot` 10 req/s; 429 on excess — [IBKR Web API pacing](https://www.interactivebrokers.com/docs/web-api/trading/usage-and-availability/pacing-limitations); older v1 docs state a global 10 req/s limit — [IBKR Web API v1 pacing](https://www.interactivebrokers.com/docs/web-api/v1/pacing-limitations.md)
- OAuth 2.0 "is not available to Individual account structures"; offered to licensed Organizations, Financial Advisors, IBrokers; individuals must use the Client Portal Gateway (Java reverse proxy through SSO); OAuth 1.0a is the only method for Third Party Developers; Gateway constraint: "all API Endpoint calls must be made on the same machine where the Client Portal Gateway was authenticated" — [IBKR OAuth 2 register](https://www.interactivebrokers.com/docs/web-api/authentication/oauth-2/register.md); [IBKR Web API authentication](https://www.interactivebrokers.com/docs/web-api/authentication); [IBKR CP Gateway limitations](https://www.interactivebrokers.com/docs/web-api/authentication/cpgw/limitations-of-the-client-portal-gateway.md)
- Web API changelog: Gateway updated to block LITE account and fractional order submissions in production beginning October 30, 2026 — [IBKR Web API changelog](https://www.interactivebrokers.com/docs/web-api/changelog)
- TWS and IB Gateway "restart once a day by design"; auto-restart setting handles this; roughly weekly after the weekend server reset a fresh login with 2FA is required — [IBKR Campus](https://www.interactivebrokers.com/campus/?p=259814). 2026 NinjaTrader forum users report unreliable reconnection after the Gateway's daily restart and manual Monday-morning reconnects — [NinjaTrader forum](https://forum.ninjatrader.com/forum/ninjatrader-8/platform-technical-support-aa/1110880-how-to-auto-manage-ib-gateway-daily-restart-without-causing-nt8-to-stop-working?p=1135472)

### Inferences
- cTrader Open API is the most MetaTrader-like substitute for an FX/CFD scalper: broker-agnostic, free, no local terminal required (unlike IBKR), with 50 msg/s per connection which is ample for a seconds-scale bot; Python SDK works but the Twisted dependency is an integration tax for asyncio-based AI pipelines.
- IBKR remains "gateway-bound": the daily restart + weekly 2FA, 50 msg/s pacing, and the exclusion of individuals from OAuth 2.0 make it operationally heavy for an unattended 24h bot; FIX at 250 msg/s is the only faster path and is not practical for individuals.
- Crypto exchanges are the only venues where a solo developer gets FIX/SBE-class protocols and sub-10 ms access by simply renting a VPS in the right AWS region.
- Darwinex Zero is MT4/MT5-only per third parties, so it does not qualify as a non-MetaTrader venue despite being bot-friendly.

## KQ4. Explicit anti-scalping / anti-HFT rules, rate limits, and hold-time rules?

### Inferences
- For a solo developer, the decision reduces to jurisdiction and instrument: non-US → Binance/Bybit perps with maker orders from a Tokyo/Singapore VPS or cTrader raw-spread FX; US → MES/MNQ via Tradovate API or Rithmic from a Chicago VPS, or Alpaca Elite for minute-scale equities.
- Seconds-scale (<30 s) holds are economically viable only where maker fees are ≤2 bps and L2 is free (crypto CEX) or where the tick/fee ratio is favourable with low per-contract commission (MES on a Lifetime plan); FX spreads at OANDA retail pricing and Alpaca IEX data do not support it.
